# Release checklist

Maintainer checklist for a public ServiceKiller release.

## Source

- [ ] Working tree clean.
- [ ] Public version/build label updated.
- [ ] `CHANGELOG.md` updated.
- [ ] Compatibility wording reflects only validated platforms.
- [ ] No private names, credentials, certificates, logs or development artifacts.
- [ ] No `bin/`, `obj/`, `.vs/` or local build output committed.
- [ ] `THIRD-PARTY-NOTICES.md` updated if dependencies/assets changed.

## Functional/security checks

- [ ] Apply/restore logic reviewed for any engine changes.
- [ ] Journal format/validator reviewed if state schema changed.
- [ ] Temporary restore task and protected worker reviewed if that code changed.
- [ ] Diagnostic output reviewed for privacy regressions.
- [ ] Defender/SmartScreen are not disabled or bypassed by the application.

## Build

- [ ] Build from the release tag/commit.
- [ ] Record compiler/Visual Studio environment.
- [ ] Compute SHA-256 of the exact release executable.
- [ ] Keep the source archive generated by GitHub tied to the tag.
- [ ] If code signing is used, sign before computing the final published SHA-256.

## Security vendor handling

- [ ] Scan/review the exact release binary.
- [ ] If detected, record the detection and submit the exact hash/file through the vendor's legitimate software-developer/false-positive process.
- [ ] Do not recommend AV exclusions as the solution.

## GitHub release

- [ ] Tag the exact commit (current public convention: `v1.1.3.01`).
- [ ] Create release notes summarizing behavior, validation scope and known limitations.
- [ ] Attach the final `ServiceKiller.exe`.
- [ ] Attach `SHA256SUMS.txt`.
- [ ] State explicitly that Windows 10 is not currently validated.
